## 2. Automatic identity semantics

`JsonlArtifactStore` and `SqliteArtifactStore` now use the same private identity
resolver. A store constructed without an explicit identity:

- infers and fingerprints every prepared item's strategy identity;
- pins the first inferred canonical identity and fingerprint;
- permits later items only when both values match;
- rejects a mismatch during preparation, before artifact lookup, append, or
  provider invocation.

The restriction applies to one live store instance. A fresh store may pin a
different automatic identity and append to the same physical artifact. Existing
records remain audit history, and replay continues to select only compatible
identity fingerprints.

An explicit store-level `ArtifactIdentity` remains a deliberate caller-owned
override. Per-item inferred identities are not compared in that mode, so one
explicit identity may describe a mixed or routed run. The caller must change
that identity whenever routing, provider, model, parser, prompt policy, or
application semantics should invalidate replay.

The mismatch raises `ArtifactError` with this exact message:

```text
Automatic artifact identity changed within one store instance. Zero-configuration identity supports one inferred execution identity per run. Use separate stores or pass an explicit ArtifactIdentity describing the mixed-strategy run.
```

The message contains no canonical identity JSON or values from
`ArtifactIdentity.extra`.

## 3. SQLite logical row validation

Strict row validation is implemented in
`SqliteArtifactStore._row_to_record()`. Every consumed row is checked before
`result_json` or `raw_context_json` is decoded.

Only a real integer equal to `ARTIFACT_SCHEMA_VERSION` is accepted. Future,
older, zero, negative, text, blob, and boolean-like representations raise
`ArtifactFormatError` identifying the invalid version, record sequence, and
item ID. Replay SQL intentionally has no logical-version predicate: an
unsupported newest matching row fails loudly instead of falling back to an
older supported row.

## 4. Stored-context decode contract

The shared private codec contract is now:

```python
decode_stored_result(
    record,
    *,
    output_decoder,
    context_decoder,
    restore_stored_context=True,
)
```

Inspection through `iter_results()` or `read_results()` restores
`raw_context` only when it was explicitly persisted. A supplied
`context_decoder` is applied; otherwise the JSON-native value is returned.
Missing or stored-null context remains `None`. Decoder failures flow through
the existing result/artifact format error path with item and sequence context.

Replay calls the codec with `restore_stored_context=False`, does not decode
historical context, and then installs the current work item's context and
submission index. It remains provider-free and marks the result as replayed.

SQLite inspection pages now project and parse `raw_context_json`. Replay
queries continue to omit it because replay neither trusts nor consumes
historical context.

- NULL-safe `context_fingerprint IS ?` lookup;

- no new public API or runtime dependency.
