## 2. Session A result

Session A now provides:

- a public `LLMCallStrategy.quota_scope` hook that defaults to
  `concurrency_scope`;
- `quota_scope=` conveniences on `CallableStrategy` and `ModelStrategy`;
- one identity-safe admission registry per execution host;
- one cooldown coordinator and RPM gate per quota scope;
- one automatic error-classifier decision per strategy identity;
- a FIFO, monotonic, continuously refilling RPM token bucket;
- one RPM reservation for every physical live attempt;
- pre-provider cancellation refunds and post-provider request consumption;

## 3. Private ownership graph

Each `ParallelBatchProcessor` or queue-less `ExecutorHost` owns:

```text
execution host
├── StrategyClassifierResolver
│   └── one cached classifier per strategy object identity
├── AdmissionRegistry
│   └── one ScopeAdmissionState per quota-scope object identity
│       ├── run-local integer ordinal
│       ├── strong quota-scope reference
│       ├── RateLimitCoordinator
│       └── QuotaGate
├── CapacityLimiter
│   └── one capacity gate per concurrency-scope object identity
└── StrategyLifecycle
    └── prepare/cleanup ownership per strategy object identity
```

Quota and concurrency ownership are intentionally independent. The four
same/different quota/concurrency combinations have an architectural regression
test.

`ParallelBatchProcessor` lazily registers scopes as work is added or executed.
A queue-less host constructed for a strategy registers that strategy's scope at
construction. `LLMGateway` and `LLMCallPool` share one queue-less host, so their
concurrent submits share state when their strategies share a scope.

## 4. Quota-scope semantics

`LLMCallStrategy.quota_scope` returns `concurrency_scope` by default.

- `CallableStrategy(quota_scope=scope)` uses the explicit object; when omitted,
  it follows the callable strategy's concurrency scope.
- `ModelStrategy(quota_scope=scope)` uses the explicit object; when omitted,
  it follows the wrapped model, matching its concurrency scope.
- A `None` result or exception from a custom `quota_scope` property falls back
  to the strategy instance.
- Object identity defines sharing. Equal-but-distinct objects do not share.
- Registry entries retain strong strategy and scope references until host
  cleanup, preventing recycled object IDs from matching stale entries.
- Each distinct scope receives the configured RPM budget. Callers must pass the
  same scope object when several strategies consume one account or gateway
  quota.
- Scope objects are never represented or serialized. Events and logs use only
  the run-local ordinal and safe strategy class name.

The caller-supplied `RateLimitStrategy` object is shared across scope
coordinators without copying. Custom implementations should therefore be
stateless or safe for concurrent calls; coordinator counters remain per scope.

## 5. Classifier-resolution semantics

`StrategyClassifierResolver` applies these rules:

1. An explicit host/processor `error_classifier=` is returned unchanged for
   every strategy.
2. Automatic mode calls a strategy instance's
   `recommended_error_classifier()` at most once.
3. The result is cached by exact strategy identity with a strong strategy
   reference.
4. `None` or a raised recommendation falls back to a fresh
   `DefaultErrorClassifier` for that strategy. A raised recommendation is
   logged but cannot break queue admission.
5. Resolver state is cleared during host cleanup.

The old batch-wide recommendation collection and mixed-provider fallback were
removed. Mixed providers now retain their matching classifiers.

Within one failure path, `_classify_error()` stores and reuses the exact
`ErrorInfo` on the exception. Retryability, rate-limit detection, suggested
wait, validation categorization, terminal category, observer data, and final
failure construction therefore do not classify the same failure through
different automatic classifiers.

Middleware may replace a work item's strategy. Preparation, classifier
resolution, quota scope, cooldown, RPM, and capacity admission all follow that
effective strategy.

## 6. RPM gate and reservation semantics

`QuotaGate` is the private unified-gate seam that Session B must extend. In
Session A it implements only request admission:

- request refill rate is `max_requests_per_minute / 60` per second;
- burst capacity is `max(1.0, max_requests_per_minute)`;
- the initial bucket is full;
- refill uses the injected production monotonic clock;
- comparisons use a small floating-point tolerance;
- positive fractional and sub-one RPM values are supported;
- one initial request is available for sub-one RPM;
- waiters are strict FIFO;
- a new arrival cannot bypass an older waiter;
- the scope owns at most one refill wake task;
- immediate admissions allocate no waiter and create no timer;
- disabled RPM creates no per-attempt waiter or child timer;
- cancellation removes an ungranted waiter promptly;
- cancellation after an unseen grant finalizes and refunds that grant;
- shutdown is idempotent, cancels the wake task, wakes all waiters, and clears
  the waiter queue.

`QuotaReservation.finalize()` is exactly-once. If provider work was never
marked started, it refunds the request unit. Once provider work was marked
started, the request remains consumed regardless of success, failure, timeout,
or cancellation.

The provider-start boundary is a synchronous callback inside
`await_with_guardrails()`, after abort registration and final deadline checks
and immediately before scheduling the strategy coroutine. This preserves the
pre-start refund/post-start consumption boundary without an await between
marking and invocation.

RPM wait is intentionally not added to the existing
`admission_wait_seconds`. Session B must add separate quota timing instead of
overloading provider-capacity timing.

## 7. Physical-attempt order

Every physical try now follows this order on the shared executor path:

1. Check the item deadline and batch abort/deadline.
2. Run `before_process` middleware under guardrails.
3. Return an existing skipped result immediately when middleware filters.
4. Resolve and prepare any middleware-replaced effective strategy.
5. Resolve the effective strategy's classifier and quota-scope state.
6. In dry-run mode, call `dry_run()` without cooldown, slow start, RPM,
   provider capacity, or cooldown-success mutation.
7. Wait for the effective quota scope's active cooldown.
8. Apply that scope's post-cooldown slow-start delay.
9. Reserve one request unit when RPM is enabled.
10. Acquire provider capacity through the independent concurrency scope.
11. Perform the final abort/deadline checks and mark the reservation started.
12. Invoke `strategy.execute()` under attempt and remaining-item guardrails.
13. Release provider capacity and finalize the request reservation.
14. Continue existing result, middleware, observer, retry, accounting,
    checkpoint, and publication behavior.

Every rate-limit retry and every content/transport retry re-enters steps 7–13
and obtains a new physical reservation. Logical attempt numbering remains
unchanged for rate-limit retries.

Artifact replay remains outside `ItemExecutor`, so it performs no cooldown,
quota, capacity, or provider work. Middleware skip returns before scope
admission. Dry run resolves identity as prescribed but neither consumes nor
mutates admission state.

## 8. Cooldown and cleanup behavior

All cooldown operations route through the current scope state:

- `wait_if_paused()`;
- `apply_slow_start()`;
- `handle_rate_limit()`;
- `on_item_success()` for successful live attempts only.

A 429 pauses only strategies sharing its quota scope. A different scope remains
admissible. `Retry-After` remains a floor, and the coordinator retains ownership
of its cooldown task so cancelling a reporting caller does not finish the
shared cooldown early.

`RATE_LIMIT_HIT`, `COOLDOWN_STARTED`, and `COOLDOWN_ENDED` include
`quota_scope_id`; the rate-limit and cooldown-start payloads also identify the
safe strategy type where applicable. No scope representation is logged.

Processor cleanup cancels batch timers and workers before shutting down all
registry entries and the compatibility coordinator. Registry shutdown attempts
both cooldown and quota-gate cleanup for every scope before raising the first
error. Strategy and artifact cleanup are still attempted if another cleanup
path fails. Queue-less host cleanup likewise attempts lifecycle, registry, and
compatibility cleanup before surfacing an error.

## 13. Known limitations and Session B risks

Session A limitations:

- The gate controls RPM only. It does not estimate, reserve, reconcile, or
  report tokens.
- The bucket is an in-process rolling smoother, not an exact emulation of every
  provider window and not cross-process coordination.
- FIFO is intentional and may create head-of-line blocking after TPM adds
  different reservation sizes.
- Scope and strategy entries are retained strongly until host cleanup; memory
  is bounded by unique registered identities, not item count.
- Quota wait has no public timing/stat field yet and is intentionally excluded
  from provider-capacity `admission_wait_seconds`.
- Broad user documentation, migration notes, changelog, benchmarks, package
  verification, and GitHub issue work remain for later sessions.

Session B must preserve these boundaries:

1. Extend the existing `QuotaGate`; do not add a second independent TPM wait
   loop. RPM and TPM must be reserved atomically at the FIFO head.
2. Extend `QuotaReservation` into the complete token reconciliation state
   machine without weakening its exactly-once, synchronous finalization and
   pre-start/post-start cancellation semantics.
3. Resolve estimates after cooldown and before quota reservation. Never hold
   provider capacity while waiting for estimation or quota.
4. Keep `on_start` at the final provider boundary after abort/deadline checks.
5. Reconcile known provider usage before application postprocessing can obscure
   it. Preserve known zero versus unknown usage and underestimation debt.
6. Add separate bounded quota timing, statistics, and events. Do not rewrite
   actual token totals with estimates or overload admission timing.
7. Preserve a new reservation for every physical rate-limit, transport,
   validation, and escalation retry while retaining logical attempt semantics.
8. Preserve replay, middleware skip, and dry-run as estimator-, quota-,
   capacity-, provider-, and admission-state-neutral paths.
9. Preserve effective middleware-replaced strategy ownership for classifier,
   quota, estimation, and capacity decisions.
10. Preserve all-scope cleanup, cancellation of unseen grants, queue/result
    invariants, checkpoint-before-publication, and safe ordinal-only scope
    observability.
11. Keep `max_requests_per_minute` positive finite float behavior, including
    sub-one values, while adding the stricter integer TPM configuration.
12. Recheck whether the private compatibility aliases are still needed; do not
    let them become a second source of execution truth.

Stop at this handoff. Session B must begin only after the independent review
gate above is satisfied.
